# perceptual-mmcache (`pmcache`)

A perceptual-similarity extension to [LMCache](https://github.com/LMCache/LMCache)
for video-LLM workloads on [vLLM V1](https://github.com/vllm-project/vllm).

## The problem

LMCache hashes multimodal inputs *bytewise* via vLLM's `MultiModalHasher`
(serializes PIL `mode` + raw NumPy pixel data, then BLAKE3). Two adjacent
video frames that look ~99% identical to a human produce completely
different `mm_hash` digests, so cross-frame KV reuse never fires — even
though most of the vision encoder's output would be reusable.

## The fix

Insert a two-tier perceptual key *before* the bytewise `mm_hash` reaches
`LMCacheConnectorV1`:

```
                    new frame
                       |
              ┌────────▼────────┐
              │  pHash (64-bit) │  Tier 1: imagehash + BK-tree
              │  Hamming ≤ K    │  (default K=5)
              └────────┬────────┘
                       |
            ┌──────────┴───────────┐
            ▼                      ▼
       no candidate          candidate bucket
            |                      |
            |             ┌────────▼────────┐
            |             │  DINOv2-small   │  Tier 2: cosine sim ≥ τ
            |             │  cosine ≥ τ ?   │  (default τ=0.98)
            |             └────┬───────┬────┘
            |                  │ yes   │ no
            ▼                  ▼       ▼
       insert new          alias        insert new
       bucket            mm_hash       bucket member
                         to anchor
                            │
                            ▼
                    LMCache sees an exact
                    mm_hash match and serves
                    its normal KV-reuse path
```

No LMCache fork required — we just rewrite the `mm_hash` that LMCache sees.

## Development environment

This repo is built on a **CPU-only Windows laptop**. The GPU-heavy runs
(vLLM + LMCache + Qwen2-VL) happen on **Colab Pro** via
[`pmcache_colab.ipynb`](pmcache_colab.ipynb), which clones this repo and
calls the public `eval.*` API as functions.

Consequences baked into the layout:

- `vllm` and `lmcache` are *not* in `pyproject.toml` (no Windows wheels).
  The Colab notebook installs them separately.
- `torch` / `transformers` / `accelerate` live in the `[vlm]` extra.
- Every module in `pmcache/` lazy-imports its heavy deps inside functions —
  `import pmcache` on a CPU-only laptop never pulls in `torch`.
- Every public eval function accepts `mock_vlm: bool = False` so the full
  harness is exercised in CI without GPU.

## Quickstart (laptop, CPU-only)

```powershell
python -m venv uchack
.\uchack\Scripts\Activate.ps1

pytest -q
```

## Quickstart (Colab GPU)

Open [`pmcache_colab.ipynb`](pmcache_colab.ipynb) in Colab Pro, switch
runtime to A100 or L4, and run all cells. The notebook handles
`vllm` / `lmcache` install, dataset prep, baseline + perceptual benchmark,
threshold sweep, and report generation.

## Environment variables

| Var | Default | Meaning |
|---|---|---|
| `PMCACHE_ENABLED` | `true` | Master switch for the shim. Set `false` to run the baseline. |
| `PMCACHE_TAU` | `0.98` | DINOv2 cosine threshold for Tier 2 verification. |
| `PMCACHE_K` | `5` | Max Hamming distance for Tier 1 pHash bucket match. |


## Known gotcha — `eval/` package name

The `eval/` directory shadows Python's built-in `eval()` *inside* modules
that live in the `eval/` package (so don't write `eval = ...` as a local
variable there). Import-site usage (`from eval.run_baseline import ...`)
works without issues. We keep the `eval/` name because the Colab notebook
hardcodes those import paths.
